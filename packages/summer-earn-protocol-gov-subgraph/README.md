# summer-earn-protocol-gov-subgraph

Indexes on-chain governance activity for the Summer.fi protocol across five chains (mainnet,
arbitrum-one, base, sonic, hyperliquid). Tracks SummerGovernor v1 and v2 proposal lifecycle events
(created, queued, executed, canceled, cross-chain sent/received), vote casting,
ProtocolAccessManager role grants and revocations, SummerGovernanceToken delegation changes, and
TimelockController scheduling/execution — including dynamically discovered timelocks via a
`TimelockControllerTemplate`. Deployed via Goldsky under the slugs `summer-protocol-gov` (mainnet),
`summer-protocol-gov-base`, `summer-protocol-gov-arbitrum`, `summer-protocol-gov-sonic`, and
`summer-protocol-gov-hyperliquid`.

## Key contracts indexed

| Data source                                    | ABI                              |
| ---------------------------------------------- | -------------------------------- |
| SummerGovernor (v1 + v2)                       | `SummerGovernor.json`            |
| ProtocolAccessManager                          | `ProtocolAccessManager.abi.json` |
| SummerGovernanceToken                          | `Votes.json`                     |
| TimelockController (static + dynamic template) | `SummerTimelockController.json`  |

Mapping handlers live in `src/mappings/`: `governance.ts`, `accessManagement.ts`, `votes.ts`,
`timelock.ts`.

## Build and deploy commands

```sh
# Generate subgraph.yaml for a chain, then codegen + build
pnpm run build:base
pnpm run build:arbitrum
pnpm run build:mainnet
pnpm run build:sonic
pnpm run build:hyperliquid

# Build + deploy a single chain (requires ../../.env with GOLDSKY credentials)
pnpm run deploy:base
pnpm run deploy:arbitrum
pnpm run deploy:mainnet
pnpm run deploy:sonic
pnpm run deploy:hyperliquid

# Deploy all chains sequentially
pnpm run deploy:all
```

`subgraph.yaml` is generated by `mustache config/<chain>.json subgraph.template.yaml` — never edit
`subgraph.yaml` directly.

## Cross-package connections

**Consumes:**

- `config/<chain>.json` — hand-maintained per-chain JSON files holding contract addresses and start
  blocks for all five chains. Nothing auto-syncs these from deployment artifacts; they must be
  updated manually after any contract deployment.
- `subgraph.template.yaml` — mustache template rendered into `subgraph.yaml` by each
  `prepare:<chain>` script.
- `../../.env` — sourced at deploy time for Goldsky API credentials.

**Consumed by:**

- `packages/summer-earn-gov-validator` — queries the staging proxy endpoints (e.g.
  `https://subgraph.staging.oasisapp.dev/summer-protocol-gov-base`) directly in
  `src/services/subgraph.ts`.
- `packages/summer-earn-interface` — references the same staging proxy URLs per chain in
  `src/config/chains.ts`.

**Gotchas:**

- Zero-address placeholders are intentional. Mainnet and arbitrum have no
  `summer-governance-token-address`; hyperevm has no `summer-governor-address` (v1). Do not treat
  these as missing config.
- All addresses are hand-copied from deployment outputs — there is no automatic sync with
  `packages/deployment`. Cross-check both when adding or upgrading a contract.
- Governor V2 addresses differ across chains. Copy-pasting between `config/` files risks silently
  deploying the wrong address on a chain.
- Adding a new chain requires: a new `config/<chain>.json` and corresponding `prepare:<chain>`,
  `build:<chain>`, and `deploy:<chain>` scripts in `package.json`, plus adding the new slug to
  `deploy:all`.
