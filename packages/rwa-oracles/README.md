# Summer Earn RWA Oracle Contracts

Smart contracts for the Summer Earn RWA Oracle system, providing Chainlink-compatible price feeds
for Real-World Assets.

## Overview

### `RwaOracle.sol`

A multi-sig secured oracle implementing `AggregatorV3Interface`:

- **Chainlink Compatible**: Implements `AggregatorV3Interface`; `latestRoundData()` returns price
  with 8 decimals.
- **Multi-Sig Security**: Requires `M-of-N` EIP-712 signatures for every price update; signatures
  must be sorted ascending by signer address.
- **Replay Protection**: Uses a contract-level `nonce` and `chainId` in every signed message.
- **Freshness Enforced**: Enforces monotonic timestamp updates; rejects prices more than 1 hour in
  the future.

### `OracleRegistry.sol`

A central discovery layer for the protocol:

- **Two-Way Lookup**: Find oracles by `ticker` (e.g. `"SPXUX"`) or by asset token address via
  `getOracleByTicker` / `getOracleByAsset`.
- **Reverse Discovery**: Map oracle addresses back to their ticker and asset via `oracleToTicker` /
  `oracleToAsset`.
- **Owner Controlled**: Only the registry owner can register oracles via `setOracle`.

### `src/test-yield/`

Three helper contracts (`TestYieldFactory`, `TestYieldToken`, `YieldPocket`) used for local/staging
testing of yield-bearing RWA tokens; not intended for production deployment.

## Development

### Prerequisites

- [Foundry](https://book.getfoundry.sh/getting-started/installation)

### Build & Test

```bash
# Compile contracts
forge build

# Run tests
forge test

# Coverage (html report)
pnpm coverage:report
```

> `package.json` exposes `coverage`, `coverage:lcov`, `coverage:report`, `format`, `format:fix`, and
> `docs:gen` scripts only. There is no `build` or `test` script — run `forge` directly.

### Deployment

A Forge script is available at `scripts/DeployRwaOracle.s.sol`; it reads configuration from
environment variables (`TICKER`, `ASSET_ADDRESS`, `ORACLE_DESCRIPTION`, `SIGNERS`, `THRESHOLD`,
optionally `REGISTRY_ADDRESS`). For automated deployments the `@summerfi/oracle-cli` package uses
`viem` to deploy and register oracles.

## Cross-Package Connections

**Consumes:**

- `@summerfi/dependencies` (workspace) — provides OpenZeppelin contracts and `forge-std` via
  remappings.

**Consumed by:**

- `packages/oracle-cli` — TypeScript CLI that deploys `RwaOracle` and `OracleRegistry` via `viem`;
  see `src/deploy.ts` and `src/deploy-yield.ts`. No workspace dependency declaration; it references
  the compiled artifacts directly.

**Gotchas:**

- There is no `build` or `test` npm script. Turbo pipelines that rely on those script names will not
  invoke Foundry for this package; run `forge build` / `forge test` manually.
- Oracle and signer lists are hand-managed off-chain (environment variables, CLI flags). If you add
  or remove a signer you must also update any scripts or deployment configs that reference the
  signer set.
- The `test-yield/` contracts are co-located in `src/` and compiled by default; they are not audited
  production contracts.
